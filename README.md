# A/B Testing: Landing Page Conversion Analysis

**Статистический анализ A/B-эксперимента по сравнению двух версий лендинга: old_page и new_page.**

## Бизнес-цель и задача исследования

**Бизнес-цель** — увеличить количество регистраций на курс за счёт повышения эффективности посадочной страницы.
**Цель исследования** — определить, приводит ли новая версия лендинга (`new_page`) к увеличению конверсии по сравнению с текущей версией (old_page).
**Основная метрика — Conversion Rate (CR)**, доля пользователей, совершивших целевое действие (регистрацию на курс).
В рамках A/B-эксперимента сравниваются две группы:
- **Control** — пользователи, которым показывается старая версия страницы.
- **Treatment** — пользователи, которым показывается новая версия страницы.
По результатам анализа необходимо определить, есть ли статистически значимое изменение конверсии и достаточно ли оснований для внедрения новой страницы.

## Этапы исследования
### 1. Загрузка и подготовка данных
Первичное изучение датасета: структура, типы переменных, пропущенные значения и основные характеристики наблюдений. Определение экспериментальных групп, целевой метрики и периода проведения теста.
### 2. Проверка корректности эксперимента
Проверка соответствия экспериментальных групп показанным страницам, обработка повторных наблюдений пользователей и анализ распределения трафика с помощью SRM (Sample Ratio Mismatch). Исследование временной динамики эксперимента.
### 3. Исследовательский анализ данных (EDA)
Расчёт конверсий контрольной и тестовой групп, визуальное сравнение показателей и изучение динамики конверсии по времени.
### 4. Формулирование статистических гипотез
Определение нулевой и альтернативной гипотез, уровня статистической значимости и критериев оценки результатов эксперимента.
### 5. Проверка гипотез
Сравнение конверсий с помощью z-теста для двух долей. Расчёт 95% доверительного интервала и оценка величины наблюдаемого эффекта.
### 6. Проверка устойчивости результатов
Применение Bootstrap для оценки распределения разницы конверсий и дополнительной проверки статистических выводов.
### 7. Дополнительный анализ
Исследование временных закономерностей и оценка статистической мощности эксперимента, включая минимальный обнаруживаемый эффект (MDE).
### 8. Итоги и рекомендации
Обобщение результатов статистического анализа, оценка ограничений исследования и формулирование рекомендаций относительно внедрения новой версии лендинга.

## 1. Первичный обзор данных

На первом этапе проведена проверка структуры датасета, типов переменных, временных границ эксперимента и наличия пропущенных значений.
Исходный датасет содержит **294 478 наблюдений и 5 переменных**.
**Единица наблюдения** — запись о показе страницы пользователю. Наличие повторных записей для одного пользователя проверяется на следующем этапе.
**Временные границы эксперимента**
Для определения периода проведения теста использованы минимальное и максимальное значения timestamp.
- Начало: 2 января 2025 года, 13:42:05.
- Окончание: 24 января 2025 года, 13:41:54.
- Продолжительность: около 22 дней.
**Результат:** все 294 478 записей содержат значения по каждому из пяти столбцов. Пропущенных значений не обнаружено.

## 2. Проверки качества и корректности эксперимента
Перед любыми статистическими тестами важно убедиться, что данные соответствуют дизайну A/B-эксперимента.

**Проверка дубликатов пользователей** (#2, 3)
Частая проблема: один и тот же `user_id` встречается несколько раз, например, пользователь заходил повторно или логирование задваивалось.
Если мы хотим интерпретировать наблюдения как независимые, обычно оставляют одно наблюдение на пользователя — самое раннее по времени.
Для примера отдельно посмотрели пользователя `762688`, который встречается в датасете дважды.

**Проверка соответствия группы и показанной страницы** (#4)
Проверим, соответствует ли экспериментальная группа той странице, которую действительно увидел пользователь.
В данных обнаружены несоответствия: часть пользователей контрольной группы видела новую страницу, а часть пользователей тестовой группы — старую.

**Чистый датасет для анализа**
1. Исключаем несоответствия group и landing_page (#5).
После фильтрации осталось **290 585 наблюдений** из исходных 294 478.
Далее проверяем дубликаты уже в очищенном от несоответствий датасете (#6).
Обнаружен **1 повторяющийся user_id**. Дополнительно просмотрены две записи пользователя 773192 (#7).
2. Сортируем наблюдения по времени и оставляем первое наблюдение на пользователя (#8).
Чтобы учитывать только первый визит каждого пользователя, сортируем данные по `user_id` и `timestamp`, после чего удаляем повторные записи. 
После очистки:
- Строк после удаления дубликатов: **290 584**.
- Уникальных user_id: **290 584**.
- Повторяющихся user_id: **0**.
Теперь у нас есть чистый датасет, в котором каждому пользователю соответствует одно наблюдение, а экспериментальная группа совпадает с показанной страницей. Его используем для дальнейшего анализа конверсий и статистических тестов.

**SRM (Sample Ratio Mismatch) (#9)** означает, что фактические доли трафика в контрольной и тестовой группах отличаются от запланированных сильнее, чем это можно объяснить случайностью.
Почему это критично:
- SRM часто указывает на проблему рандомизации или маршрутизации: часть пользователей не попадает в одну из групп, срабатывают фильтры или возникают ошибки логирования.
- При SRM p-value по метрике становится менее достоверным: мы сравниваем не «случайно равные» группы.
Как проверяем:
- Задаём ожидаемое распределение пользователей между группами — 50/50.
- Используем χ²-тест согласия для сравнения ожидаемых и наблюдаемых частот.
Статистическая значимость χ² = 0.00446 — очень маленькое значение.
p = 0.94675 — значительно больше порога 0.05.
НЕТ признаков SRM - распределение пользователей между группами практически идеально соответствует запланированному соотношению 50/50.
Следовательно, проверка SRM не выявила статистически значимых отклонений в распределении трафика между контрольной и тестовой группами.

**Временная динамика (#10)**
Проверим, нет ли перекосов по времени (например, одна группа запускалась позже или тест «переключали» в процессе).
Для этого посмотрим, как изменялось количество пользователей в контрольной и тестовой группах по дням эксперимента.
Для визуализации используем линейный график с разделением по группам `control` и `treatment`.
Результат:
На протяжении основного периода эксперимента количество пользователей в обеих группах остаётся примерно на одном уровне — около 6 500–6 800 человек в день.
Линии контрольной и тестовой групп практически совпадают. Небольшие ежедневные колебания присутствуют, но выраженного перекоса в пользу одной из групп не наблюдается.
В первый и последний дни количество пользователей заметно ниже, что связано с неполными сутками наблюдения на границах эксперимента.
Контрольная и тестовая группы получали сопоставимый объём трафика на протяжении эксперимента.
Признаков того, что одна из групп была запущена значительно позже другой или что распределение трафика резко изменялось в процессе тестирования, на графике не наблюдается.

## 3. EDA и основная метрика
Здесь мы рассматриваем основную метрику эксперимента: **конверсию (converted)**, то есть долю пользователей, совершивших целевое действие.
Единица анализа — пользователь (каждый пользователь учитывается один раз).
**Конверсия по группам (#11)**
Рассчитаем конверсию для контрольной (control) и тестовой (treatment) групп.
Для каждой группы определим:
- mean — средняя конверсия (CR);
- sum — количество пользователей, совершивших целевое действие;
- count — общее количество пользователей;
- cr_percent — конверсия в процентах.
Для наглядного сравнения построим столбчатую диаграмму конверсий по группам (#12).
Конверсия контрольной группы составляет 12.04%, тестовой — 11.88%. Конверсия новой страницы немного ниже старой, однако по одному визуальному сравнению нельзя определить, является ли это различие статистически значимым.
**Конверсия по дням недели (#13)**
Проверим, отличаются ли конверсии по дням недели и есть ли взаимодействие «группа × день недели».
Для этого выделим день недели из timestamp и рассчитаем среднюю конверсию для каждой группы.
Для сравнения построим столбчатую диаграмму конверсий по дням недели с разделением на контрольную и тестовую группы. (#14)
Конверсия отличается в зависимости от дня недели. В пятницу и понедельник тестовая группа показывает немного более высокую конверсию, чем контрольная. В остальные дни конверсия контрольной группы выше.
При этом различия между группами остаются относительно небольшими. Наблюдаемые колебания пока являются результатами исследовательского анализа и сами по себе не подтверждают статистически значимого эффекта.

## 4. Гипотезы
Для проверки влияния новой версии лендинга на конверсию сформулируем две статистические гипотезы:
- **H0 (нулевая гипотеза):** конверсия в регистрацию на новом лендинге статистически значимо не изменилась по сравнению со старым.
- **H1 (альтернативная гипотеза):** конверсия в регистрацию на новом лендинге статистически значимо изменилась.
**Уровень значимости (α):** по умолчанию возьмём 0.05. Это означает, что если на самом деле эффекта нет, вероятность «ложной тревоги» при выбранном критерии составляет около 5%.
Поскольку нас интересует любое изменение конверсии — как увеличение, так и снижение, — используем двустороннюю проверку гипотез.

## 5. Статистический тест для основной метрики
Поскольку основная метрика бинарная (converted принимает значения 0 и 1), мы сравниваем две доли.
Смотрим на:
- **Оценку эффекта:** p_treat - p_control — разницу конверсий между тестовой и контрольной группами.
- **Доверительный интервал (ДИ):** насколько эффект может отличаться при повторении эксперимента.
- **p-value:** насколько наблюдаемые различия согласуются с H0 (эффекта нет).
Для больших выборок (n больше 30) можно использовать **z-тест**, так как при достаточно больших размерах групп распределение разности выборочных долей хорошо описывается нормальным приближением.
Используем доверительный интервал и проверку устойчивости через bootstrap, поскольку одно только p-value не показывает величину эффекта и диапазон неопределённости.

**Z-тест разницы долей (#15)**
Для сравнения конверсий контрольной и тестовой групп используем двусторонний z-тест.
Разница конверсий отрицательная: конверсия новой страницы немного ниже конверсии старой.
При этом **p-value = 0.1899 больше 0.05**, поэтому оснований отвергнуть нулевую гипотезу нет.

**Доверительный интервал для разницы долей (#16)**
Дополнительно рассчитаем 95% доверительный интервал для разницы конверсий с использованием нормального приближения.
Полученный 95% доверительный интервал: [−0.3938; +0.0781] процентного пункта.
Интервал включает ноль, следовательно, наблюдаемая разница может быть совместима как с небольшим снижением, так и с небольшим увеличением конверсии.

В рамках этого проекта мы не знаем экономику внедрения новой страницы.
- p-value больше 0.05 — нулевую гипотезу не отвергаем.
- Ноль внутри доверительного интервала — разница статистически незначима при выбранном уровне значимости.
Таким образом, по результатам z-теста **статистически значимого изменения конверсии новой версии лендинга не обнаружено**.
Это не означает, что две страницы полностью одинаковы: полученных данных недостаточно для подтверждения различия при выбранном уровне значимости.

## 6. Проверка устойчивости: bootstrap для разницы конверсий
Нормальное приближение для долей обычно хорошо работает на больших выборках, но bootstrap полезен как дополнительная проверка устойчивости результата.
- Для каждой группы бутстрепом пересэмплируем пользователей.
- Считаем конверсию в каждой полученной выборке.
- Строим распределение разницы конверсий между тестовой и контрольной группами.
Здесь используется доверительный интервал, построенный по процентилям полученного bootstrap-распределения.

**Расчёт bootstrap-интервала (#17)**
Для оценки разницы конверсий используется функция bootstrap_diff(). На каждой итерации случайным образом выбираются наблюдения с возвращением отдельно из контрольной и тестовой групп, после чего рассчитывается разница средних конверсий.
Количество bootstrap-итераций — 3 000.
Полученный 95% доверительный интервал:[−0.3815; +0.0907] процентного пункта. Интервал включает ноль, поэтому статистически значимого изменения конверсии по результатам bootstrap не обнаружено.
Визуализация bootstrap-распределения (#18)
Для наглядного анализа построена гистограмма распределения разницы конверсий (treatment - control).
На графике отмечены:
- распределение полученных bootstrap-разниц;
- наблюдаемая разница конверсий;
- нижняя и верхняя границы 95% доверительного интервала.
Распределение сосредоточено преимущественно в области отрицательных значений, что соответствует немного более низкой конверсии тестовой группы. При этом доверительный интервал пересекает ноль.
Результат bootstrap практически совпадает с результатом z-теста, что подтверждает предыдущий вывод.
**Статистический вывод: H0 не отвергаем.** На основании полученных данных статистически значимого различия между конверсиями контрольной и тестовой групп не обнаружено. При этом отсутствие статистически значимого различия не означает, что конверсии двух страниц доказанно одинаковы.

  ## 7. Мощность и минимально детектируемый эффект (MDE)
Если эффект мал, A/B-тест может быть не способен его обнаружить даже при наличии реального различия между группами.
Посчитаем ориентировочный размер выборки на группу для заданного **MDE (Minimum Detectable Effect)** — минимального эффекта, который мы хотим обнаружить с заданной статистической мощностью.

**Предположения:**
- Baseline — конверсия контрольной группы (базовый уровень).
- MDE — 0.2 п.п. (0.002), 0.5 п.п. (0.005) или 1.0 п.п. (0.01).
- Alpha (α) — 0.05, уровень статистической значимости.
- Power — 0.8 (80%), статистическая мощность теста.

**Расчёт необходимого размера выборки (#19)**
Для расчёта используется функция `sample_size_two_proportions()`, которая оценивает необходимое количество пользователей в каждой группе для сравнения двух долей.
Чем меньше эффект, который мы хотим обнаружить, тем больше пользователей необходимо включить в эксперимент.
При MDE = 0.2 п.п. требуется около 418.5 тыс. пользователей в каждой группе, тогда как при MDE = 1.0 п.п. достаточно примерно 17.2 тыс.
В текущем эксперименте после очистки данных осталось около 145 тыс. пользователей в каждой группе. Этого количества достаточно по приведённому расчёту для обнаружения эффекта 0.5 п.п. или 1.0 п.п. при заданных предположениях, но недостаточно для эффекта 0.2 п.п.
Таким образом, отсутствие статистически значимого различия между версиями лендинга может быть связано в том числе с тем, что реальный эффект слишком мал для надёжного обнаружения при текущем размере выборки.

## 8. Итоги и интерпретация результатов
В данном проекте был проведён полный цикл анализа A/B-эксперимента: от очистки и валидации данных до статистической оценки эффекта и проверки его устойчивости. Ниже зафиксированы ключевые выводы, напрямую вытекающие из проведённого анализа.
**Корректность данных и постановки эксперимента**
Перед оценкой эффекта мы убедились, что данные допускают корректную статистическую интерпретацию:
- Наблюдения с несоответствием между назначенной группой и фактически показанной страницей были исключены, что устранило выявленные случаи смешения воздействий.
- Данные были приведены к уровню «один пользователь — одно наблюдение», что исключает искажение метрики за счёт неодинаковой активности пользователей.
- Проверка SRM не выявила статистически значимого перекоса в распределении трафика между группами.
- Анализ динамики по времени не показал признаков систематического временного сдвига, способного объяснить различия между группами.
Таким образом, после выполненных проверок данные можно использовать для дальнейшего анализа эффекта.

**Результаты основного анализа**
Сравнение конверсий в контрольной и тестовой группах показало незначительную разницу, величина которой находится вблизи нуля.
Z-тест разности долей не выявил статистически значимого эффекта на уровне значимости 5%, а 95% доверительный интервал включает ноль, что означает отсутствие убедительных доказательств улучшения или ухудшения метрики.
С практической точки зрения наблюдаемая оценка эффекта является малой, однако для определения её экономической значимости необходимы дополнительные данные о ценности регистрации и затратах на внедрение новой страницы.

**Проверка устойчивости вывода**
Bootstrap-оценка распределения эффекта показала концентрацию значений вблизи нуля без выраженного смещения в положительную или отрицательную сторону.
Полученный доверительный интервал согласуется с результатом z-теста и также включает ноль.
Согласованность выводов двух методов указывает на то, что отсутствие статистически значимого эффекта не является особенностью только одного способа анализа.

**Интерпретация результата**
На основании проведённого анализа нет статистически убедительных доказательств того, что новая версия страницы приводит к изменению конверсии по сравнению с контрольной.
Это не означает, что эффект гарантированно равен нулю. В рамках данного объёма данных и текущей постановки эксперимента возможный эффект либо слишком мал для надёжного обнаружения, либо неотличим от случайных колебаний.
С учётом полученных результатов внедрение новой версии страницы на основании данного эксперимента не рекомендуется. Для дальнейшего принятия решения можно рассмотреть проведение дополнительного эксперимента с заранее определённым MDE, необходимой мощностью и оценкой экономической значимости ожидаемого эффекта.
